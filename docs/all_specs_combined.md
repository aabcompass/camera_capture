## Часть 2: ТЗ всего ядра (`core_spec.md`)

# Техническое задание: Camera Data Capture IP (всё ядро)

## 1. Назначение и границы

**[REQ]** IP принимает непрерывные кадры научных данных от высокоскоростной камеры, обеспечивает до-триггерную историю, при наступлении разрешённого триггера собирает заданное количество полных кадров и записывает в память PS Zynq-7000. Каждый фрагмент начинается с фиксированной преамбулы. Конфигурация и чтение состояния — через AXI4-Lite. Прерывания не используются.

**Целевая платформа:** Zynq-7000 XC7Z035 (скоростной класс −2), Vivado 2023.1, единый тактовый домен 200 МГц. **[CURRENT]** Верхний RTL `camera_capture_top`, параметр `USE_XPM` выбирает XPM или поведенческий FIFO. Обращение к DDR — через 64-битный AXI3 master, который соединяется с PS `S_AXI_HP` без AXI interconnect (целевой замысел).

## 2. Входные данные и пропускная способность

| Параметр | Значение / требование |
|---|---|
| Поток камеры | `S_AXIS`: `TDATA[63:0]`, `TVALID`, `TLAST`, `TREADY` |
| Backpressure | **[REQ] `S_AXIS_TREADY = 1` постоянно**; камера не может останавливаться |
| Размер кадра | **768 байт = 96 слов × 64 бита** |
| Граница кадра | `TLAST` на 96-м действительном слове |
| Поток | **307 200 000 байт/с = 400 000 кадров/с** |
| Такт | **200 МГц**; идеальная пропускная способность 64-битного интерфейса при `TVALID=1` — 1,6 ГБ/с |
| Ошибки камеры | Преждевременный или отсутствующий `TLAST`, невозможность записи в FIFO — диагностируемая ошибка; повреждённый частичный кадр не передаётся как валидный |

**[CURRENT]** После START контроллер делает синхронизацию на кадр: игнорирует входные слова до следующего действительного `TLAST` включительно, затем начинает сохранение полного кадра. Все сигналы событий кадра относятся к тому же тактовому фронту, что и входное слово.

## 3. Источники триггера

**[REQ]** Поддержать три независимых источника:

1. **Алгоритмический:** `S_AXIS_TRG_TVALID=1` и `S_AXIS_TRG_TDATA[63:0] != 0`.
2. **Внешний:** передний фронт `ext_trig`, синхронизированный в домен `clk`.
3. **Внутренний:** одиночный программный импульс и периодический генератор.

**[CURRENT]** Маска разрешения трёх источников; при совпадении приоритет метаданных `external > algorithmic > internal`. Передаваемые данные триггера равны `S_AXIS_TRG_TDATA` только для выбранного алгоритмического источника, для остальных равны нулю. `timestamp[63:0]` и trigger data защёлкиваются на фронте **принятого** триггера. Для внешнего источника это фронт после синхронизации; исходное асинхронное время события не восстанавливается.

**[REQ]** В период занятости фрагмента новый триггер не начинает новую передачу. **[CURRENT]** Статистика различает принятые события (не более одного за такт) и пропущенные события (до трёх за такт при совпадении источников). В `BUFFER_FILLING` события не принимаются; политика учёта пропущенных событий описана в модуле Trigger Controller.

## 4. Буфер и до-триггерные кадры

| Параметр | Контракт |
|---|---|
| Предыстория | `0 ≤ n_prev_frames ≤ 64` и `n_prev_frames < n_frames` |
| Общее количество кадров фрагмента | `2 ≤ n_frames ≤ 131072` |
| Количество фрагментов за START | `n_fragments ≥ 1`, дополнительно ограничивается размером выделенной памяти |
| Логический объём FIFO | **100 кадров = 9600 слов = 76800 байт** |
| Хранение | **[CURRENT]** 65 бит на слово `{TLAST,TDATA}`, физическая XPM FIFO 16384 слов с логическим лимитом 9600 |

**[REQ]** До триггера сохраняются `n_prev_frames` последних полных кадров и текущий незавершённый кадр; более старые полные кадры удаляются. **[CURRENT]** Контроллер выталкивает из FIFO целые кадры (до `TLAST`), не обрывая кадр посередине. После триггера остаточное количество лишних PRE кадров удаляется перед передачей.

**[REQ]** Кадр, содержащий фронт принятого триггера, является **первым post-trigger кадром**, включая случай совпадения триггера с `TLAST`. Всего в успешном фрагменте записывается **ровно `n_frames` полных кадров**: `n_prev_frames` до него и `n_frames − n_prev_frames` после, считая кадр триггера.

**[REQ]** Переполнение FIFO — фатальная ошибка; новое содержимое не должно молча перезаписывать непрочитанные данные; ядро инициирует контролируемое завершение уже принятых AXI-транзакций и переходит в `ERROR`. **[CURRENT]** `fifo_overflow_count` считает отвергнутые записи (слова), а не обязательно единичные эпизоды переполнения; это отдельный предмет решения.

## 5. Формат фрагмента в DDR

**[REQ]** Формат: **128 байт преамбулы + `n_frames × 768` байт кадров**. Адрес начала фрагмента кратен 128. Все кадры передаются в исходной последовательности слов, без переупаковки. Строго little-endian для многобайтовых полей преамбулы.

| Смещение, байт | Размер | Поле |
|---|---:|---|
| `0x00` | 4 | `header_id`, программируемый идентификатор |
| `0x04` | 4 | `fragment_index`, начиная с 0 в каждом запуске |
| `0x08` | 8 | Защёлкнутый `timestamp` |
| `0x10` | 8 | Защёлкнутый `trigger_data` либо 0 |
| `0x18` | 32 | `aux_data` из 8 регистров AXI-Lite |
| `0x38` | 72 | Padding: повторяемые 32-битные слова `0x12345678` |
| `0x80` | 768 | Кадр №0; далее последовательно все кадры |

**[CURRENT]** В RTL преамбула выдаётся шестнадцатью 64-битными словами, первый — `{fragment_index, header_id}`, слова 7–15 — `0x1234567812345678`. Ровно 16 слов на burst и 6 bursts на кадр. **Количество burst-фрагмента:** `1 + 6×n_frames`.

### Объём памяти

```
fragment_bytes = 128 + 768 * n_frames
run_bytes      = n_fragments * fragment_bytes
fragment_addr(i) = mem_addr + i * fragment_bytes
```

**[REQ]** Перед разрешением START проверяются параметры, границы 32-битного адресного пространства и весь буфер: `run_bytes <= MEM_BUFFER_BYTES`; `mem_addr` кратен 128; `MEM_BUFFER_BYTES > 0`; исключается 32-битное переполнение адреса. Граница окончания интервала считается **исключительной**; ровно `2^32` допустимо как конец диапазона.

**[CURRENT]** Дополнительно writer проверяет **каждый burst** `addr .. addr+127` на принадлежность разрешённому диапазону. Отдельная проверка нужна для защиты от ошибки адресной логики после START.

## 6. Интерфейс памяти AXI3

**[REQ/CURRENT]** M_AXI basic write master, ширина WDATA 64, канал `AW/W/B`, `AWLEN=15`, `AWSIZE=3`, `AWBURST=INCR`, каждый burst 128 байт; частично заполненных burst нет. `WSTRB=0xFF`. Задержки `AWREADY`, `WREADY`, `BVALID` должны корректно обрабатываться с сохранением `VALID/DATA` до handshake. Максимум **4 незавершённых по BRESP AW** (`MAX_OUTSTANDING=4`).

**[CURRENT]** Одновременно активен один источник дескриптора burst, но ранее выданные AW могут ожидать B-ответа — это не четыре полностью параллельных канала подачи burst. Все IDs сейчас равны нулю; ответы сопоставляются по порядку выдачи AW. Успех фрагмента устанавливается **только после всех корректных BRESP**, а не после передачи последнего WDATA.

## 7. Управление и состояния

Состояния (значения в регистре STATUS, реализация):

`0 IDLE → 1 BUFFER_FILLING → 2 TRIG_WAIT → 3 DATA_TRANSFER → 4 AFTER_TRANSFER → (1 BUFFER_FILLING | 6 END_STATE | 0 IDLE)`.

При фатальной ошибке — `5 ERROR`, возврат по разрешённой команде очистки после безопасного завершения, сброса FIFO и освобождения пути записи.

- `START`: только из `IDLE` без неснятых ошибок; сначала многотактовая проверка SHADOW-параметров, затем атомарная фиксация ACTIVE и заполнение FIFO.
- `TRIG_WAIT`: хранение PRE окон, ожидание принятого триггера.
- `DATA_TRANSFER`: передача преамбулы и полных кадров, текущий кадр не обрезается.
- `AFTER_TRANSFER`: очистка FIFO, ожидание готовности, следующий фрагмент либо END.
- `STOP`: завершить текущий кадр камеры, не записывать неполные кадры; если триггера ещё не было — без DDR-записи; в передаче записать только доступное число **полных** кадров и дождаться BRESP; результат отметить как частичный/остановленный; затем `IDLE`.
- `ERROR`: новые burst не выдавать, уже принятые AW/W/B корректно завершить/дождаться; после восстановления — явное действие PS.
- `END_STATE`: конец заданного числа фрагментов; выход в IDLE по команде от PS.

**[REQ]** Приоритет при совпадениях: STOP выше триггера; fatal error выше обычного STOP. **[CURRENT]** На STOP выдаётся уточнённый `stop_target_frames` для `burst_packer`, а `halt_new` применяется только при фатальном прерывании.

## 8. Конфигурация, статус, диагностика

**[REQ]** Полноценный 32-битный AXI4-Lite slave, без IRQ; конфигурация `n_frames`, `n_prev_frames`, `n_fragments`, `MEM_ADDR`, `MEM_BUFFER_BYTES`, триггеры, header ID, AUX; команды START/STOP/CLEAR; статус FSM и ошибок; статистика DDR и триггеров.

**[CURRENT]** SHADOW можно обновлять во время активного захвата, но ACTIVE не меняется до следующего успешно проверенного START. Пока START проходит проверку — SHADOW-конфигурацию записывать запрещено во избежание TOCTOU. Регистрная карта: [register_map.md](register_map.md).

**[CURRENT после патча №4]** `triggers_accepted_total` и `triggers_missed_total` — **48-битные** счётчики modulo `2^48`, представленные 64-битными регистрами чтения с нулями в старших 16 битах. На внутренней реализации каждый счётчик разделён на три 16-битных сегмента. Этот выбор **не содержался в исходном ТЗ**; подлежит согласованию.

## 9. Тактирование, реализация, ограничения

- **[REQ]** Один `clk = 200 МГц`, без отдельного домена DDR-ввода в проекте IP.
- Внешний `ext_trig` асинхронен и проходит синхронизацию; временная привязка к камере имеет соответствующую неопределённость.
- **[CURRENT]** XPM BRAM FIFO и поведенческий FIFO для тестов; при штатной сборке `USE_XPM=1`.
- **[VERIFY]** Фактическое выполнение Timing после placement/routing в Block Design с PS, подключение clock/reset и реальная конфигурация HP-порта.
- **[VERIFY]** Длительность и распределение блокировок DDR/HP в реальной системе не известны; 100 кадров FIFO не гарантируют отсутствие переполнений при произвольно долгой остановке DDR.

## 10. Критерии приёмки

1. Сохранение точного содержимого и порядка 96 слов всех записанных кадров и 128-байтной преамбулы.
2. Корректная выборка PRE и первого POST при триггере в середине кадра и на TLAST.
3. START с некорректными параметрами отвергается **до** DDR; адрес и размер памяти проверяются без арифметического wrap.
4. `S_AXIS_TREADY` не опускается; потеря записи/повреждение кадра приводит к диагностируемой ошибке.
5. Никакого незаявленного AXI3 burst за пределами буфера; ошибки BRESP фиксируются; успешный фрагмент предполагает все `OKAY` BRESP.
6. STOP и ERROR не оставляют «висящих» принятых транзакций при отвечающем AXI slave.
7. Регрессионные тесты для XPM и поведенческого FIFO и долгого потока проходят.
8. **[VERIFY]** После Place & Route все Setup/Hold/и остальные релевантные Timing constraints выполнены при 200 МГц.

## 11. Что в ТЗ является реализационным решением

Фиксированные **100 кадров буфера**, **48-битная статистика**, **паддинг 0x12345678**, **две burst-банки**, **четыре outstanding BRESP**, отдельные счётчики некоторых стадий и двойная защита диапазона — разные по степени обязательности элементы. Матрица оценки: [architecture_review.md](architecture_review.md). Изменения интерфейсов и регистрационной карты требуют отдельного решения — не следует автоматически объявлять их «избыточными».

## Часть 3: Карта регистров (`register_map.md`)

# AXI4-Lite: карта регистров и программный контракт

**Адреса:** смещения относительно base address IP. Все доступы по 32 бита, выравнивание 4 байта. **Режим:** AXI4-Lite, самостоятельное принятие AW и W, `WSTRB[3:0]`; регистры SHADOW доступны для чтения; ACTIVE — внутренний снимок при разрешённом START. Неизвестные адреса: `DECERR`; запись в RO/недопустимая команда: `SLVERR`.

| Offset | Имя | Доступ | Значение |
|---|---|---|---|
| `0x000` | COMMAND | WO (RO=0) | bit0 START, bit1 STOP, bit2 CLEAR_ERROR, bit3 CLEAR_STATS; команды одиночные, одновременно несколько команд не допускается |
| `0x004` | STATUS | RO | state[3:0], busy[4], stop_pending[5], trigger_latched[6], capture_complete[7], axi_busy[8], fifo_empty[9], fifo_full[10], config_error[11], runtime_error[12] |
| `0x008` | ERROR_FLAGS | RO sticky | ошибки, см. ниже |
| `0x00C` | TRIGGER_ENABLE | RW | bit0 algorithmic, bit1 external, bit2 internal |
| `0x010` | N_FRAMES | RW | 2…131072 |
| `0x014` | N_PREV_FRAMES | RW | 0…64, строго меньше N_FRAMES |
| `0x018` | N_FRAGMENTS | RW | ≥1; размер пробега обязан помещаться в буфер DDR |
| `0x01C` | MEM_ADDR | RW | первый адрес DDR, выровнен по 128 |
| `0x020` | HEADER_ID | RW | 32-битный идентификатор заголовка |
| `0x024`…`0x040` | AUX_0…AUX_7 | RW | восемь последовательных 32-битных слов, всего 256 бит |
| `0x044` | INT_TRIG_PERIOD | RW | период в тактах `clk`, >0 когда периодический режим разрешён |
| `0x048` | INT_TRIG_CTRL | RW/command | bit0 одиночный импульс (команда), bit1 periodic_enable (состояние) |
| `0x04C` | RESERVED | **не отображён** | в RTL нет адреса 0x04C; доступ выдаёт `DECERR` |
| `0x050` | LAST_ERROR_CODE | RO | последняя ошибка/код (событийное поле статистики) |
| `0x054` | LAST_ERROR_ADDR | RO | адрес последней ошибки AXI |
| `0x058` | FIFO_LEVEL | RO | число 65-битных слов в логическом FIFO |
| `0x05C` | FRAMES_CAPTURED | RO | число кадров, принятых по данным камеры в текущем фрагменте |
| `0x060` | FRAMES_SENT | RO | полные кадры, все W beats которых приняты AXI W каналом |
| `0x064` | FRAMES_COMMITTED | RO | полные кадры, подтверждённые успешными BRESP |
| `0x068` | FRAGMENTS_COMPLETED_TOTAL | RO | накопительное число завершённых фрагментов |

### ERROR_FLAGS

| Бит | Смысл |
|---:|---|
| 0 | Переполнение FIFO / отклонённая запись камеры |
| 1 | Ошибка AXI BRESP, отличная от DECERR (в частности SLVERR) |
| 2 | AXI BRESP DECERR |
| 3 | Ошибка формата кадра (TLAST) / ошибка формата packer |
| 4 | Недопустимое N_FRAMES |
| 5 | Недопустимое N_PREV_FRAMES |
| 6 | N_FRAGMENTS = 0 |
| 7 | MEM_ADDR не кратен 128 |
| 8 | Зарезервирован в рассматриваемой реализации |
| 9 | MEM_BUFFER_BYTES=0 либо run не помещается в него |
| 10 | Ошибка адресного диапазона (переполнение или выход burst за границу) |
| 11 | Включён периодический триггер с периодом 0 |
| 12 | AXI-протокольная ошибка writer |
| 13 | Неверный STOP target от packer |
| 14…31 | В рассматриваемой реализации не назначены |

**Сведения:** биты 4–11 ставятся startup guard; 0–3, 10, 12, 13 — datapath/top. Hardware set имеет приоритет над software clear. Биты статусной агрегированной ошибки в `STATUS` — **производные** от ERROR_FLAGS, не самостоятельные latch.

### Ограничения на команды

- START разрешён только в IDLE, когда нет неснятых ошибок и нет активной проверки конфигурации.
- STOP допустим как команда завершения/выхода из END_STATE; обработка зависит от текущего состояния FSM.
- CLEAR_ERROR разрешён в безопасном IDLE либо в ERROR после завершения очистки.
- CLEAR_STATS разрешён в IDLE либо END_STATE.
- Во время многотактовой START-validation записи в SHADOW конфигурации возвращают SLVERR.
- 64-битные статистические значения читаются парами **сначала LO, затем HI**. После патча №4 физический счётчик 48 бит, его 64-битный readback дополнен нулями до 64 бит.

### Вопросы, требующие решения

1. Нужна ли вся текущая карта диагностики и все LAST_* регистры?
2. Нужно ли сохранять 64-битный программный ABI для статистики при внутреннем 48-битном счётчике?
3. Что должно означать «ошибка переполнения»: число отклонённых слов или число эпизодов?
4. Должна ли конфигурация быть доступна к изменению во время захвата (SHADOW/ACTIVE) или проще разрешать запись только в IDLE?

## Часть 4: Архитектурный аудит (`architecture_review.md`)

# Архитектурный аудит: что можно упростить

**Назначение:** этот документ — перечень вариантов на обсуждение, **не** план обязательных изменений. Отличаем ограничение физической системы от решения RTL, принятого для удобства разработки. Прежде чем убирать механизм, нужно решить, сохраняем ли его внешнее поведение.

## 1. Что нельзя упрощать без изменения задачи

| Свойство | Почему обязательно |
|---|---|
| `S_AXIS_TREADY = 1` | Источник физически нельзя остановить; без буферизации остаётся риск потерь |
| 96 слов/кадр, полные кадры, проверка TLAST | Без этого нарушится формат научных данных |
| Семантика PRE/POST, включая триггерный кадр | От неё зависит научный смысл выборки |
| STOP по границе кадра | Нельзя сформировать «полкадра» как полноценный результат |
| Проверка памяти на весь run до START | Защита DDR от записи мимо выделенной области |
| Корректное завершение AXI AW/W/B и BRESP | Иначе возможна ложная запись/успешность и нарушение AXI |
| FIFO, позволяющий принять поток на фоне DDR backpressure | Иначе безостановочный источник потеряет данные |
| Наблюдаемое аварийное состояние | Без него потеря данных будет скрытой |

## 2. Кандидаты на упрощение (с оценкой)

| Тема | Что сейчас | Вариант | Выигрыш / риск | Приоритет |
|---|---|---|---|---|
| **Триггерная статистика** | **[CURRENT]** 48 бит, 3×16 сегмента, наружу 64 | Оставить; альтернативно 32 бита с документированным wrap, или 64 бита с секциями | Меньше арифметики, но семантика wrap/совместимость ПО | **Зафиксировать 48**, если хватает |
| **`frame_sequence`** | 64-битный внутренний счётчик в `frame_input_ctrl`; top никуда не выводит | Убрать или сделать 32-битным | Вероятнее всего Vivado уже выбросил неиспользуемую логику: **почти нет эффекта Timing** | Низкий |
| **FIFO 100 кадров** | Логическая глубина 9600×65, XPM физически 16384 | Пересчитать глубину для реального DDR stall, PRE≤64 | Экономия BRAM, но риск переполнения при задержках HP | После измерения backpressure |
| **`MAX_OUTSTANDING=4`** | До четырёх AW ожидают BRESP, дескриптор AW/W один одновременно | Сделать 1–2 при достаточной полосе DDR | Упростит очередь ответов, но снизит степень скрытия латентности DDR | Тест throughput |
| **2×128B банки packer** | Две регистровые банки для скрытия backpressure | Одна банка или BRAM | Меньше регистров, риск остановки передачи/FIFO pressure | Средний |
| **64-битные адресные вычисления writer** | `next_addr` 64, per-burst `+128` и сравнения 64 бит | 32-битный byte-адрес с отдельно зарегистрированным overflow-флагом, либо 25-битный индекс 128B-bursts | Потенциально сократит теперь самый длинный **положительный** Setup-путь, но особенно опасно при границе 4 GiB | **Не трогать до P&R** |
| **Проверка памяти дважды** | На START — весь run, в writer — каждый burst | Убрать per-burst check, если весь адресный тракт формально доказан | Выигрыш Timing, **но уменьшение защиты DDR**; особенно нежелательно для standalone DMA | Низкий |
| **SHADOW + ACTIVE** | Два набора конфигурации | Запретить RW во время BUSY и удалить SHADOW | Меньше FF/логики, но ухудшится удобство подготовки следующего запуска; надо изменить software ABI | Средний |
| **Регистрная карта диагностики** | Много 32-битных LAST_*/счётчиков и 64-битные SNAP | Удалить неиспользуемые ПО | Меньше FF, ширины mux/readback, но потеря трассируемости ошибок | После определения требований ПО |
| **Периодический триггер** | 32-битный периодный счётчик | Сократить только при допустимом max period | Меняется максимальный период и формат регистра; исходное поведение сохранить иначе | Низкий |
| **`n_fragments`** | 32-битная конфигурация и run counters | Сузить только при фактическом лимите выделенной DDR области | Меньше логики проверки, но меняет предел количества фрагментов | Низкий |
| **Паддинг преамбулы** | Фиксированные 72 байта и 0x12345678 | Не генерировать padding? | **Нельзя без изменения формата**: 128B заголовок — часть контракта DDR | Нет |
| **Две модели FIFO** | XPM и поведенческая | Оставить поведенческую только в SIM | В продуктивном нет дополнительной аппаратной цены; помогает отладке | Не менять |

## 3. Пять принципиальных вопросов для владельца системы

1. **Сколько на самом деле могут длиться задержки DDR/HP?** Средней пропускной способности недостаточно для расчёта нужной ёмкости FIFO. 100 кадров = 76 800 байт, это примерно 250 мкс непрерывного входа при 307,2 МБ/с **без чтения**. Но в PRE-режиме часть буфера уже занята (до 64 кадров), свободно может быть гораздо меньше.
2. **Нужно ли считать до трёх одновременных триггеров отдельно?** Можно определять `missed` как *количество тактов с хотя бы одним пропущенным событием* вместо *количества отдельных событий*. Это упростит логику, но изменит трактовку статистики и сравнение тестов.
3. **Что является достаточным пределом для счётчиков?** Для accepted 48 бит — большой запас. Для missed при трёх событиях/такт математически wrap через ~5,43 суток непрерывного пика. При 32 битах и 400k принятых/с accepted переполнится за ~2,98 часа; при 200 млн событий/с — за ~21,5 с. Не объединять «счётчик кадров» с «счётчиком событий» по частотам.
4. **Можно ли менять конфигурацию без остановки текущего запуска?** Если нет — SHADOW/ACTIVE можно пересмотреть. Если да — двойная конфигурация имеет смысл.
5. **Нужны ли четыре outstanding при фактическом HP/DDRx режиме?** Провести эксперимент `MAX_OUTSTANDING=1/2/4` под воспроизводимой задержкой BRESP и WREADY. Держать то, что обеспечивает требуемую пропускную способность с запасом.

## 4. Что именно произошло с Timing

После патча №4 в синтезе **Setup уже положительный: WNS = +0,162 нс, TNS = 0**. Поэтому радикальное переписывание критического тракта сейчас может ухудшить положение и создать функциональные риски. Оставшееся `WHS = −0,036 нс` — Hold на этапе синтеза; сначала проверить P&R. Подробнее: [timing_snapshot.md](timing_snapshot.md).

## 5. Как безопасно принимать решения

- Зафиксировать baseline Git commit, включая патч №4, только после проверки `git diff`, `git diff --check` и регрессии (она уже прошла по сообщению пользователя).
- Каждому упрощению дать **отдельный issue**: требование, план изменения software ABI, новый тест, ожидаемый выигрыш LUT/FF/BRAM/Timing.
- Изменять **один модуль/свойство за итерацию**; не путать сокращение разрядности с изменением определения статистики.
- До удаления per-burst защиты памяти доказать, что все допустимые/аварийные пути не могут выдать адрес вне буфера; лучше оставить защиту.
- После каждого изменения сравнивать полную регрессию, utilisation, **Setup и Hold после P&R**, а не один WNS синтеза.

## 6. Приоритет для следующей инженерной итерации

**Рекомендуется не писать новый RTL немедленно.** Сначала проверить *post-route* Timing в PS Block Design. Если нарушится Setup на пути writer→packer — прицельно рассмотреть архитектуру вычисления адреса/диапазона в `axi3_write_master`. Если нарушится только Hold — смотреть средства физической оптимизации Vivado, а не сокращать диагностические счётчики вслепую.

## Часть 7: axi3_write_master (`modules/axi3_write_master.md`)

# ТЗ модуля `axi3_write_master.sv`

**Роль:** защищённая передача 128-байтных burst в PS `S_AXI_HP` (AXI3 64-bit), учёт outstanding AW и подтверждение целых кадров только по BRESP.

## Интерфейс

- Control: `start`, `halt_new` (**fatal only**), `start_addr[31:0]`, `mem_base_addr[31:0]`, `mem_buffer_bytes[31:0]`, `packer_done`.
- Packer: `burst_valid/ready`, `burst_is_preamble`, `burst_ends_frame`, `burst_word_count_minus_one`, `p_wdata[63:0]`, `p_wvalid`, `p_wready`, `p_wlast`.
- AXI3 master: AW (`AWID[5:0]`, `AWADDR[31:0]`, `AWLEN[3:0]`, `AWSIZE[2:0]`, `AWBURST`, `AWLOCK`, `AWCACHE`, `AWPROT`, `AWVALID/READY`), W (`WID[5:0]`, `WDATA[63:0]`, `WSTRB[7:0]`, `WLAST`, `WVALID/READY`), B (`BID[5:0]`, `BRESP`, `BVALID/READY`).
- Status: `active`, `drain_done`, `writer_done`, `range_error`, `bresp_error`, `protocol_error`, `last_error_addr`, `last_bresp`, `outstanding[2:0]`, `bursts_issued/w_sent/committed`, `frames_committed[17:0]`, `preamble_committed`, `current_write_addr[31:0]`.

## Контракт

1. Фиксированные **16 beats**, `AWLEN=15`, `AWSIZE=3`, INCR, `WSTRB=0xFF`; адрес каждого burst кратен 128.
2. Не принимать descriptor при отсутствии свободного budget outstanding, ошибке или нарушении границ памяти. Writer самостоятельно проверяет каждый burst `[next_addr,next_addr+128)` на принадлежность `[mem_base,mem_base+mem_buffer_bytes)` и отсутствие перехода за 4 GiB.
3. AW и W — независимые handshake: W может быть принят до AW; уже выставленный AWVALID/WVALID удерживается до READY даже при появлении STOP/fatal.
4. `MAX_OUTSTANDING=4` — максимум **AW, ожидающих B**. В текущем RTL только **один descriptor одновременно находится на стадиях AW/W**, что следует отличать от четырёх параллельных потоков данных.
5. `BID` сейчас константный 0, BRESP сопоставляются по порядку AW. Ошибка `SLVERR/DECERR` фиксируется; `frames_committed` увеличивается только по `OKAY` BRESP, помеченному окончанием кадра.
6. `halt_new` не отменяет принятый descriptor; завершить (drain) уже выданные AW/W/B. `writer_done` требует packer_done, no pending transactions, no fault и подтверждённую преамбулу.
7. Обычный STOP не использует `halt_new`: пока packer отдаёт полные кадры, writer должен дописать их и дождаться BRESP.

## Текущая реализация

Внутренняя `next_addr`/границы — 64 бит для точной проверки интервала и границы 4 GiB; `next_addr += 128`. Кольцевая очередь metadata для максимум 4 BRESP, `AWID/WID=0`.

## Проверки

Stalls на AW/W/B, BRESP tail error, неправильный BID, WLAST protocol error, диапазон ровно до 4 GiB, overflow одного burst, 4 outstanding, `halt_new` во время AW/W/B.

## Открытые вопросы / Timing

**[CURRENT]** После патча №4 худший **положительный** Setup-путь идёт через `next_addr` → range guard → packer reset/enable. **[OPTION]** Снизить ширину адресной арифметики или зарегистрировать разрешение burst, сохранив защиту 4 GiB. Пока не менять без Place & Route: WNS уже положительный.

## Часть 8: axi_lite_regs (`modules/axi_lite_regs.md`)

# ТЗ модуля `axi_lite_regs.sv`

**Роль:** 32-битный AXI4-Lite slave, команда/конфигурация ядра, статусы, sticky ошибки, чтение 64-битной статистики. Не выполняет саму валидацию DDR и не управляет FIFO напрямую.

- Разрешения: `allow_start`, `allow_clear_error`, `allow_clear_stats`, `cfg_write_lock`, `run_start_pulse`.
- SHADOW поля: `cfg_*`, ACTIVE поля: `active_*`, статусы FSM и тракта данных.

## Основной контракт

1. Раздельно захватывать AW и W, поддерживать произвольный порядок их handshake. Удерживать B/R до READY; уважать `WSTRB` на каждой конфигурационной записи.
2. Команды выдавать **один раз на одну принятую запись**. Запрещать несовместимые комбинации команд, неверные биты, запись RO и неизвестные адреса корректными AXI BRESP.

5. `error_flags` sticky, аппаратное установление имеет приоритет над CLEAR_ERROR в тот же такт.
6. Чтение 64-битных accepted/missed: сначала LO, оно запоминает HI; отдельный HI read возвращает захваченное значение, а не «рваную» пару.

## Карта регистров

Полная карта, доступы, биты и исключения — **[../register_map.md](../register_map.md)**. Адреса до `0x0B4`; `0x04C` **не отображён** в текущем RTL. Версия `IP_VERSION_VALUE=0x00010000` по умолчанию.

AW/W в разном порядке, одиночный и пакетный R, stalls, write byte strobes, invalid addresses, invalid commands, read only, разрешения FSM, snapshots и два последовательных запуска, статистика на границе 32 бит, reserved read.

## Обсуждение упрощения

**[OPTION]** Сократить список STATUS/LAST_* регистров и убрать SHADOW/ACTIVE только после определения потребностей программного обеспечения PS и версионирования ABI; снижение ресурсов может оказаться небольшим относительно выигрыша в удобстве.

## Часть 9: burst_packer (`modules/burst_packer.md`)

# ТЗ модуля `burst_packer.sv`

**Роль:** формировать DDR-поток как преамбулу 128 байт и последовательность полных 768-байтных кадров, разбитую на 128-байтные AXI burst. Модуль не занимается AXI-адресами/BRESP.

## Интерфейс

- Управление: `start`, `abort`, `n_frames[17:0]`, `stop_target_valid`, `stop_target_frames[17:0]`.
- Поля преамбулы: `header_id[31:0]`, `fragment_index[31:0]`, `timestamp[63:0]`, `trigger_data[63:0]`, `aux_data[255:0]`.
- Источник FIFO (FWFT): `in_data[64:0]={TLAST,DATA}`, `in_valid`, `in_ready`.
- Выход descriptor: `burst_valid/ready`, `burst_is_preamble`, `burst_ends_frame`, `burst_word_count_minus_one` (**всегда 15**).
- Выход данных: `w_data[63:0]`, `w_valid`, `w_ready`, `w_last`.
- Диагностика: `active`, `packer_done`, `format_error`, `target_error`, `frames_packed[17:0]`, `frames_sent[17:0]`, `bursts_sent[31:0]`.

## Контракт

1. Каждый burst **ровно 16 слов × 64 бита**, WLAST только на последнем слове. Дескриптор burst принимается writer **до** передачи его W-слов.
2. Структура: burst #0 — 128-байтная преамбула; далее **ровно 6 bursts на каждый 96-словный кадр**.
3. Преамбула: `word0={fragment_index,header_id}`, word1 timestamp, word2 trigger data, words3–6 AUX (по 64 бита), words7–15 повторяют `0x1234567812345678`.
4. Уровни VALID и WDATA сохраняются при отсутствии READY; слово FIFO читается только при реальном handshake и наличии свободного банка.
5. По TLAST контролировать, что кадр завершается именно на 96-м слове; нарушение — `format_error`.
6. `stop_target_valid` уменьшает целевой объём **после определения границы STOP** и только в пределах `[frames_packed, initial n_frames]`; целое число полных кадров, никаких частичных burst/кадров.
7. `frames_sent` считается по W handshake полного кадра, **не** по BRESP. `packer_done` не означает успешную фиксацию в DDR.

## Текущая реализация

Два локальных банка по `16×64` бит, логика fill/send и метаданные burst. Формат константен — никакого variable burst length.

## Проверки

Побайтовое сравнение header + frame data, FAST/STALL, два банка одновременно (one fill, one send), TLAST ошибок, STOP target, запрет дальнейшего извлечения FIFO, неизменность WDATA при stall.

## Варианты

**[OPTION]** Одна burst-банка может сэкономить регистры, но снизит способность поглощать паузы AXI. Количество банков следует выбирать по требованию к throughput, а не только по FF.

## Часть 10: camera_capture_top (`modules/camera_capture_top.md`)

# ТЗ модуля `camera_capture_top.sv` — верхний уровень

**Роль:** интеграция всех блоков IP, физический интерфейс потоковой камеры, триггеров, AXI4-Lite и AXI3 DDR. Не дублирует функциональную обработку кадров/триггеров внутри top.

## Интерфейсы

- `clk`, `rst`: единый синхронный функциональный домен 200 МГц; текущие leaf блоки используют активный высокий `rst`.
- Камера: `s_axis_tdata[63:0]`, `s_axis_tvalid`, `s_axis_tlast`, выход `s_axis_tready` всегда 1.
- Триггер: `s_axis_trg_tdata[63:0]`, `s_axis_trg_tvalid`, `ext_trig`, вход `timestamp[63:0]`.
- AXI4-Lite slave: независимые AW/W/B/AR/R; адрес/данные 32 бит, WSTRB=4.
- AXI3 master для Zynq HP: AWID/WID/BID по 6 бит, адрес 32, WDATA 64, WSTRB 8, burst length=16 слов; остальные стандартные сигналы AW/W/B.
- Параметр `USE_XPM` выбирает реализацию FIFO, для платы `1`.

## Функции и инварианты

1. Соединить START validation (`mem_range_guard`) и атомарный `run_start_pulse` с AXI-Lite SHADOW→ACTIVE.
2. Обеспечить передачу событий `frame_stored`, `trigger_accept` на **том же** тактовом фронте; начало `burst_packer`/writer допускает нужную тактовую задержку для latch metadata.
3. Во время WAIT поддерживать sliding PRE history, в TRANSFER подавать FIFO кадры на packer, после завершения делать FIFO flush.
4. Соединить ошибки входного кадра, FIFO, packer и writer с sticky ERROR_FLAGS и FSM. Входные fault-сигналы не должны образовывать комбинаторную петлю через `capture_enable`.
5. На штатный STOP **не** подавать `writer_halt_new`: packer должен закончить допустимые полные кадры. На фатальную ошибку halt/abort должен останавливать новые descriptor, не сбрасывая уже принятые AXI транзакции.
6. Включить **полный исходный текст ТЗ** комментарием в top RTL — это согласованное организационное требование.

## Границы ответственности

Top только маршрутизирует/объединяет ошибки и статусы; конкретные правила находятся в отдельных модулях. Нельзя считать `writer_done` эквивалентом `packer_done`.

## Критерии проверки

- Интеграционный end-to-end XSIM: корректная преамбула, непрерывное содержимое фреймов, границы DDR, BRESP.
- Stress и faults на `USE_XPM=1`.
- Синтез с теми же RTL и XDC в Git; финальная верификация после подключения PS HP.

## Что обсудить

[OPTION] Уменьшение числа status-соединений/счётчиков, не используемых ПО. Не менять интерфейс без согласования register ABI и regression test.

## Часть 12: capture_fifo_ctrl (`modules/capture_fifo_ctrl.md`)

# ТЗ модуля `capture_fifo_ctrl.sv`

**Роль:** превратить обычный 65-битный FIFO в логический сдвиговый буфер полных кадров с PRE-историей, удалением старых кадров и доступом на чтение после триггера.

## Интерфейс

- Запись: `write_data[64:0]`, `write_req`, `write_accepted`, `frame_stored`.
- Управление: `fifo_flush`, `n_prev_frames[6:0]`, `drop_enable`, `trigger_accept`, `transfer_enable`.
- Чтение на packer: `read_data[64:0]`, `read_valid`, `read_ready`.
- Мониторинг: `fifo_level_words[13:0]`, `complete_frames[7:0]`, `logical_full`, `overflow_pulse`, `overflow_sticky`, `drop_active`, `drops_remaining[7:0]`, `triggered`, `transfer_ready`, `popped_frame_done`, `fifo_ready`.

## Контракт

1. Логический объём FIFO — **9600 слов = 100×96**. В момент переполнения новые записи отклонять, не затирать старые данные.
2. При `drop_enable` и без триггера хранить последние `n_prev_frames` **полных** кадров плюс текущий незавершённый; сбрасывать только целые избыточные кадры до `TLAST`.
3. Если триггер совпал с удалением кадра, правильно учитывать уже завершившийся drop; после принятия триггера удалить ровно число избыточных PRE кадров.
4. Выдавать данные packer только после выполнения `transfer_ready`, когда избыточные PRE кадры удалены, `triggered=1` и есть хотя бы один полный кадр.
5. `complete_frames` меняется **только по успешно принятому TLAST слова в FIFO** и по извлечённому/удалённому TLAST. Частично записанный кадр полным не считается.
6. Одновременные push/pop при логическом full могут разрешить push, если pop освобождает позицию именно на том же фронте.
7. На flush обнулить накопленные статусы/состояние сдвигового окна; дождаться физической готовности FIFO после reset.

## Параметры текущего RTL

`FRAME_WORDS=96`, `LOGICAL_DEPTH=9600`, `PHYSICAL_DEPTH=16384`, `USE_XPM`.

## Проверки

0/1/64 PRE кадров, длинная серия кадров, trigger на TLAST, одновременно drop и incoming TLAST, full + pop + push, давление на чтение, overflow pulse, flush/restart, XPM/behavioral.

## Что можно менять

**[OPTION]** Пересчитать 100 кадров под реальный worst-case DDR stall. Сокращение FIFO без теста максимальной непрерывной задержки DDR непосредственно увеличивает риск потери данных.

## Часть 13: capture_main_fsm (`modules/capture_main_fsm.md`)

# ТЗ модуля `capture_main_fsm.sv`

**Роль:** контроллер жизненного цикла захвата/фрагмента, без прямого формирования AXI данных. Согласует START-validation, sync камеры, PRE window, trigger, STOP, AXI drain и recovery.

## Основные интерфейсы

- Управление: `cmd_start/stop/clear_error`, `sticky_error_flags`, ACTIVE параметры `active_n_frames/prev/fragments/mem_addr`.
- Guard handshake: `guard_check_req/done/ok/error_flags/fragment_bytes`, `run_start_pulse`, `cfg_write_lock`.
- Frame/FIFO: `fifo_ready`, `fifo_complete_frames`, `frame_sync_ready`, `frame_stored`, `capture_stopped`, `trigger_accept`, `fatal_error`; выходы `frame_sync_request`, `capture_enable`, `frame_stop_request`, `fifo_flush`, `fifo_drop_enable`, `fifo_transfer_enable`.
- Trigger permissions: `trigger_run_active`, `trigger_accept_enable`, `trigger_count_enable`.
- Packer/writer: `fragment_start_pulse`, `packer_abort`, `writer_halt_new`, `stop_target_valid`, `stop_target_frames[17:0]`, `fragment_n_frames[17:0]`, `fragment_addr/index[31:0]`, `writer_done`, `writer_drain_done`, `writer_frames_committed`, `writer_preamble_committed`.
- STATUS: `fsm_state[3:0]`, busy/stop/trigger/complete, frames_captured, run_fragments_completed, fragment_complete_pulse, last_fragment_*.

## Состояния

| Значение | Имя | Контракт |
|---:|---|---|
| 0 | IDLE | Пустой/сброшенный буфер, принимать только допустимый START; validation до ACTIVE |
| 1 | BUFFER_FILLING | Синхронизация на TLAST и накопление PRE; не принимать trigger |
| 2 | TRIG_WAIT | Поддержание rolling PRE history, разрешение первого valid trigger |
| 3 | DATA_TRANSFER | Запуск packer/writer, получение требуемого числа полных кадров, обновление STOP target |
| 4 | AFTER_TRANSFER | FIFO flush/recovery, возврат к FILL или END/IDLE |
| 5 | ERROR | Ожидание безопасной очистки; возврат через разрешённый CLEAR_ERROR |
| 6 | END_STATE | Нужное число фрагментов выдано, ожидание STOP/выхода в IDLE |

## Инварианты и приоритеты

1. START разрешён из IDLE с нулевыми sticky errors; сначала guard; `run_start_pulse` только на успешном `guard_check_done`.
2. `active_*` меняются NBA в такт `run_start_pulse`; захват `active_mem_addr` начинается **на следующем такте**, не в тот же NBA.
3. При принятом триггере: `frames_captured = n_prev_frames + frame_stored` (если триггер на TLAST, кадр триггера уже засчитан как первый POST). Writer и packer стартуют после фиксации метаданных.
4. В DATA_TRANSFER `frames_captured` считает завершённые кадры, ограничивается `active_n_frames`. При штатном достижении цели дождаться `writer_done` (BRESP).
5. STOP имеет приоритет над триггером в одном такте; завершает текущий кадр, обновляет `stop_target_frames`, допускает только полные кадры. Если до триггера — без DDR.
6. Fatal выше STOP: прекратить выдачу новых burst, дождаться drain уже принятых AXI транзакций при отвечающем slave; ERROR и последующая очистка.
7. Успешные полные фрагменты увеличивают индекс и адрес на `fragment_bytes`; partial STOP фиксирует статус, но не считается полноценным выполнением `n_fragments`.

## [CURRENT] Патчи №1 и №2

- Удалён дублирующий `stop_limit`: в безопасный момент `stop_target_frames = frames_captured[17:0]`.
- Операции next frame count / сравнение обрезаны до 18 бит с сохранением внешнего 32-битного статуса.
- Для корректности на границах обязательны тесты однотактных сочетаний STOP/TLAST/fatal.

## Верификация

Команды из разных состояний, отвергнутый START и delayed check_done, trigger на TLAST, несколько фрагментов и stride, STOP до/в процессе передачи, STOP+trigger, STOP+fatal, ERROR после AW/W/B drain.

## Открытые вопросы

**[OPTION]** Упростить отдельные статусы STOP/trigger_pending только после доказательства эквивалентности всех приоритетных комбинаций: здесь цена ошибки существенно выше потенциального выигрыша FF.

## Часть 14: capture_statistics (`modules/capture_statistics.md`)

# ТЗ модуля `capture_statistics.sv`

**Роль:** накопительная диагностика завершённых фрагментов, ошибок FIFO и writer, а также сохранение последнего кода/адреса ошибки.

## Интерфейс

- Reset/control: `clk`, `rst`, `clear_stats`, `clear_error`.
- Events: `fragment_complete_pulse`, `fifo_overflow_pulse`, `writer_range_error`, `writer_bresp_error`, `writer_last_bresp[1:0]`, `writer_protocol_error`, `writer_last_error_addr[31:0]`, `error_set_mask[31:0]`.
- Outputs (32-bit): `fragments_completed_total`, `fifo_overflow_count`, `axi_error_count`, `last_error_code`, `last_error_addr`.

## Контракт

1. `fragments_completed_total` инкрементируется на подтверждённый полный фрагмент.
2. `fifo_overflow_count` инкрементируется на **каждый такт отказа записи** (`overflow_pulse`); если важно считать эпизоды, это отдельное изменение ТЗ.
3. `axi_error_count` инкрементируется при входе в writer fault episode (`writer_error && !writer_error_prev`), а **не** по каждому BRESP.
4. `clear_stats` обнуляет три накопительных счётчика; `clear_error` очищает поля последней ошибки, с приоритетом обработки текущей ошибки, указанным RTL.
5. `last_error_code/addr` сохраняют информацию о последней диагностируемой ошибке; нет прерываний.

## Текущая реализация

Все эти регистры 32 бита. Оригинальное ТЗ требует **статистику ошибок**, но точный состав LAST_* и ширину счётчиков определили при разработке.

## Верификация

Серия отказов FIFO каждое слово, длинный assert writer error (один эпизод), снятие ошибки/повторное появление, CLEAR_STATS во время неактивной системы, CLEAR_ERROR и запись новой ошибки.

## Упрощение

**[OPTION]** Можно объединить некоторые накопительные поля, но лучше сначала определить, какие показатели необходимы для поиска пропусков данных в реальной DDR-системе. Разница между *событием*, *тактом* и *эпизодом* должна быть явно согласована.

## Часть 15: frame_input_ctrl (`modules/frame_input_ctrl.md`)

# ТЗ модуля `frame_input_ctrl.sv`

**Роль:** приём нефильтруемого потока камеры и контроль кадровой структуры. Не управляет AXI3 и не выбирает pretrigger depth.

## Входы / выходы

| Категория | Сигналы |
|---|---|
| Clock/reset | `clk`, `rst` |
| AXIS camera | `s_axis_tdata[63:0]`, `s_axis_tvalid`, `s_axis_tlast`; `s_axis_tready=1` |
| Control | `sync_request`, `capture_enable`, `stop_request` |
| FIFO push | `fifo_wr_data[64:0]={TLAST,DATA}`, `fifo_wr_req`, `fifo_wr_accepted` |
| Events | `frame_start`, `frame_done`, `captured_frame_done`, `capture_stopped`, `frame_format_error`, `fifo_write_error` |
| Diagnostic | `frame_active`, `frame_word_index[6:0]`, `frame_sync_ready`, `frame_sequence[63:0]` |

## Контракт

1. Один полный кадр ровно 96 слов (768 байт); `TLAST` ровно на слове 95 (индексация с 0).
2. Фронт `sync_request` имеет приоритет; на нём данные выбрасываются. До ближайшего **действительного** TLAST данные игнорируются. Следующее valid слово — начало нового кадра.
3. `s_axis_tready=1` **всегда** независимо от заполнения FIFO. Во время запрета capture слова выбрасываются, а не оказывают backpressure.
4. `fifo_wr_req && fifo_wr_accepted` означает запись **на этом же фронте**. Это grant, не ACK на следующем фронте.
5. STOP завершает текущий кадр; когда STOP совпадает с первым словом нового кадра — завершает этот начатый кадр. После STOP запись не возобновляется до нового sync_request. Приоритет RESET > SYNC > STOP.
6. Неправильный TLAST формирует `frame_format_error`. Если часть ошибочного кадра уже попала в FIFO, контроллер системы обязан удалить её при обработке ошибки.
7. События `frame_start/frame_done/captured_frame_done/capture_stopped/...` — **комбинационные однотактные события**, относящиеся к тому же фронту, что и входные слова/команды.

## Текущая реализация

`FRAME_WORDS=96` фиксировано; `frame_sequence` 64-битный счётчик полноценных увиденных кадров, сбрасываемый при `sync_request` и reset.

## Верификация

Пустые TVALID, короткий/длинный кадр, отсутствие TLAST, TLAST при STOP, STOP на первом слове, sync во время кадра, FIFO отказ, отсутствие записи после STOP.

## Кандидат на упрощение

**[OPTION]** Удалить или сузить `frame_sequence` (top его никуда не передаёт); ожидаемый выигрыш после синтеза всего top минимален, если логика уже оптимизирована из-за неиспользуемости.

## Часть 16: mem_range_guard (`modules/mem_range_guard.md`)

# ТЗ модуля `mem_range_guard.sv`

**Роль:** проверить ВСЮ конфигурацию запуска до разрешения сбора/DDR, без выполнения AXI транзакций. Не заменяет per-burst защиту writer.

## Интерфейс

- Запрос `check_req` (однотактный из IDLE), `n_frames[31:0]`, `n_prev_frames[31:0]`, `n_fragments[31:0]`, `mem_addr[31:0]`, `mem_buffer_bytes[31:0]`, `periodic_enable`, `int_trig_period[31:0]`.
- Ответ `check_done` (pulse), `check_ok`, `check_error_flags[31:0]`, `fragment_bytes[31:0]`, `total_required_bytes[63:0]`, `buffer_end_exclusive[63:0]`.

## Условия успеха

```
2 <= n_frames <= 131072
0 <= n_prev_frames <= 64
n_prev_frames < n_frames
n_fragments >= 1
mem_addr % 128 == 0
mem_buffer_bytes > 0
fragment_bytes = 128 + 768*n_frames
required_bytes = fragment_bytes * n_fragments
required_bytes <= mem_buffer_bytes
mem_addr + mem_buffer_bytes <= 2^32
!periodic_enable || (int_trig_period > 0)
```

64-битная арифметика и проверка допустимости `n_frames` должны предотвращать wrap, превращающий недопустимую конфигурацию в кажущийся малым размер. Значение **ровно `2^32`** допустимо только как `buffer_end_exclusive`, не как адрес записи.

## Текущая реализация после оптимизации v1.1

Многотактовый конвейер: snapshot всех входных полей на `check_req` → вычисление размера фрагмента → частичные произведения → cross terms → полный объём → атомарная публикация результата с `check_done`. FSM обязан ждать `check_done` и не использовать устаревший `check_ok`. SHADOW нельзя менять на протяжении проверки (блокировка в AXI-Lite).

## Ошибки

`ERROR_FLAGS[4]` неверные frames; `[5]` неверные prev; `[6]` нулевые fragments; `[7]` неправильное выравнивание; `[9]` нулевой/малый буфер; `[10]` выход за 4 GiB; `[11]` нулевой период включённого internal periodic.

## Верификация

Граничные значения всех параметров, max×max произведение, точно достаточный буфер, нехватка 1 байта, region_end 4GiB, snapshot после изменения внешних входов, многотактовое ожидание, удержание статуса до следующего запроса.

## Возможность сокращения

**[OPTION]** Изменить разрядности под допустимый software protocol, но не возвращать огромный комбинаторный путь размер×количество×сравнение: он ранее ломал 200 МГц.

## Часть 17: trigger_ctrl (`modules/trigger_ctrl.md`)

# ТЗ модуля `trigger_ctrl.sv`

**Роль:** формировать синхронные события из трёх источников, разрешать только первый допустимый триггер, фиксировать метаданные и вести счётчики принятых/пропущенных событий.

## Интерфейс

- Источники: `s_axis_trg_tdata[63:0]`, `s_axis_trg_tvalid`, `ext_trig_async`, `int_single_pulse`, `int_periodic_enable`, `int_period_cycles[31:0]`.
- Конфигурация: `trigger_enable[2:0]`, `timestamp[63:0]`.
- Разрешения FSM: `run_start`, `run_active`, `accept_enable`, `count_enable`, `clear_stats`.
- События: `alg_event`, `ext_event`, `int_event`, `trigger_event`, `trigger_accept`, `trigger_event_count[1:0]`, `trigger_missed_events[1:0]`.
- Метаданные: `trigger_source[1:0]`, `trigger_data[63:0]`, `latched_timestamp`, `latched_trigger_data`, `latched_trigger_source`.
- Статистика: `triggers_accepted_total[63:0]`, `triggers_missed_total[63:0]` (программный контракт, физическая разрядность после патча №4 — 48).

## Контракт

1. Алгоритмическое событие только при TVALID и ненулевом TDATA; ext — фронт после двух `ASYNC_REG` синхронизаторов; internal — одиночная команда или периодический импульс.
2. Маска `trigger_enable`: bit0 alg, bit1 ext, bit2 internal.
3. События и принятие — комбинационные same-cycle. `trigger_accept` только при `accept_enable && count_enable`, не на START; FSM снимает accept_enable при STOP/fatal.
4. Совпадающие источники: приоритет metadata **external > algorithmic > internal**. Алгоритмические данные в заголовок только при выбранном algorithmic source; иначе 0.
5. Счётчики: accepted += 1 при успешном принятии, missed += (`event_count - accept`) на активном участке счёта; до 3 пропущенных за один такт; во время inactive считать не нужно.
6. `run_start` обнуляет фазу периодического генератора. Первый periodic tick на N-м активном такте при периоде N>=1. Нулевой период при разрешённом periodic отвергает startup guard.
7. Защёлкнутые timestamp/trigger_data/source меняются только при принятии и сохраняются до следующего принятия/reset; `clear_stats` не стирает metadata.

## [CURRENT] Патч №4

Два счётчика 48 бит modulo `2^48`, реализованные **3×16-битными секциями** и выдаваемые в регистровую карту как нулерасширенные 64 бита; принятие до одного и пропуски 0–3 за такт. Это реализация, не исходное требование. Патч №3 с заменой сравнения периода был отозван из-за ухудшения Timing.

## Проверки

Экстремальные period=1/2/максимальное, совпадения 2/3 sources, внешняя синхронизация, STOP+trigger, timestamp latch, статусы accepted/missed в disabled states, `clear_stats`; перенос через 16/32 бита, wrap на 48 бит и `missed += 2/3`.

## Открытые решения

**[OPTION]** Сократить статистику ещё сильнее либо считать события с объединением совпадений, но это изменит наблюдаемую семантику. Отдельно решить, нужна ли 64-битная **программная** карта readback.
