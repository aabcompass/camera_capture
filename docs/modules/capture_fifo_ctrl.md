# ТЗ модуля `capture_fifo_ctrl.sv`

**Роль:** превратить обычный 65-битный FIFO в логический сдвиговый буфер полных кадров с PRE-историей, удалением старых кадров и доступом на чтение после триггера.

## Интерфейс

- Запись: `write_data[64:0]`, `write_req`, `write_accepted`, `frame_stored`.
- Управление: `fifo_flush`, `n_prev_frames[6:0]`, `drop_enable`, `trigger_accept`, `transfer_enable`.
- Чтение на packer: `read_data[64:0]`, `read_valid`, `read_ready`.
- Мониторинг: `fifo_level_words[13:0]`, `complete_frames[7:0]`, `logical_full`, `overflow_pulse`, `overflow_sticky`, `drop_active`, `drops_remaining[7:0]`, `triggered`, `transfer_ready`, `popped_frame_done`, `fifo_ready`.

## Контракт

1. Логический объём FIFO — **9600 слов = 100×96**. В момент переполнения новые записи отклонять, не затирать старые данные.
2. При `drop_enable` и без триггера хранить последние `n_prev_frames` **полных** кадров плюс текущий незавершённый; сбрасывать только целые избыточные кадры до `TLAST`.
3. Если триггер совпал с удалением кадра, правильно учитывать уже завершившийся drop; после принятия триггера удалить ровно число избыточных PRE кадров.
4. Выдавать данные packer только после выполнения `transfer_ready`, когда избыточные PRE кадры удалены, `triggered=1` и есть хотя бы один полный кадр.
5. `complete_frames` меняется **только по успешно принятому TLAST слова в FIFO** и по извлечённому/удалённому TLAST. Частично записанный кадр полным не считается.
6. Одновременные push/pop при логическом full могут разрешить push, если pop освобождает позицию именно на том же фронте.
7. На flush обнулить накопленные статусы/состояние сдвигового окна; дождаться физической готовности FIFO после reset.

## Параметры текущего RTL

`FRAME_WORDS=96`, `LOGICAL_DEPTH=9600`, `PHYSICAL_DEPTH=16384`, `USE_XPM`.

## Проверки

0/1/64 PRE кадров, длинная серия кадров, trigger на TLAST, одновременно drop и incoming TLAST, full + pop + push, давление на чтение, overflow pulse, flush/restart, XPM/behavioral.

## Что можно менять

**[OPTION]** Пересчитать 100 кадров под реальный worst-case DDR stall. Сокращение FIFO без теста максимальной непрерывной задержки DDR непосредственно увеличивает риск потери данных.
