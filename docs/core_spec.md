# Техническое задание: Camera Data Capture IP (всё ядро)

## 1. Назначение и границы

**[REQ]** IP принимает непрерывные кадры научных данных от высокоскоростной камеры, обеспечивает до-триггерную историю, при наступлении разрешённого триггера собирает заданное количество полных кадров и записывает в память PS Zynq-7000. Каждый фрагмент начинается с фиксированной преамбулы. Конфигурация и чтение состояния — через AXI4-Lite. Прерывания не используются.

**Целевая платформа:** Zynq-7000 XC7Z035 (скоростной класс −2), Vivado 2023.1, единый тактовый домен 200 МГц. **[CURRENT]** Верхний RTL `camera_capture_top`, параметр `USE_XPM` выбирает XPM или поведенческий FIFO. Обращение к DDR — через 64-битный AXI3 master, который соединяется с PS `S_AXI_HP` без AXI interconnect (целевой замысел).

## 2. Входные данные и пропускная способность

| Параметр | Значение / требование |
|---|---|
| Поток камеры | `S_AXIS`: `TDATA[63:0]`, `TVALID`, `TLAST`, `TREADY` |
| Backpressure | **[REQ] `S_AXIS_TREADY = 1` постоянно**; камера не может останавливаться |
| Размер кадра | **768 байт = 96 слов × 64 бита** |
| Граница кадра | `TLAST` на 96-м действительном слове |
| Поток | **307 200 000 байт/с = 400 000 кадров/с** |
| Такт | **200 МГц**; идеальная пропускная способность 64-битного интерфейса при `TVALID=1` — 1,6 ГБ/с |
| Ошибки камеры | Преждевременный или отсутствующий `TLAST`, невозможность записи в FIFO — диагностируемая ошибка; повреждённый частичный кадр не передаётся как валидный |

**[CURRENT]** После START контроллер делает синхронизацию на кадр: игнорирует входные слова до следующего действительного `TLAST` включительно, затем начинает сохранение полного кадра. Все сигналы событий кадра относятся к тому же тактовому фронту, что и входное слово.

## 3. Источники триггера

**[REQ]** Поддержать три независимых источника:

1. **Алгоритмический:** `S_AXIS_TRG_TVALID=1` и `S_AXIS_TRG_TDATA[63:0] != 0`.
2. **Внешний:** передний фронт `ext_trig`, синхронизированный в домен `clk`.
3. **Внутренний:** одиночный программный импульс и периодический генератор.

**[CURRENT]** Маска разрешения трёх источников; при совпадении приоритет метаданных `external > algorithmic > internal`. Передаваемые данные триггера равны `S_AXIS_TRG_TDATA` только для выбранного алгоритмического источника, для остальных равны нулю. `timestamp[63:0]` и trigger data защёлкиваются на фронте **принятого** триггера. Для внешнего источника это фронт после синхронизации; исходное асинхронное время события не восстанавливается.

**[REQ]** В период занятости фрагмента новый триггер не начинает новую передачу. **[CURRENT]** Статистика различает принятые события (не более одного за такт) и пропущенные события (до трёх за такт при совпадении источников). В `BUFFER_FILLING` события не принимаются; политика учёта пропущенных событий описана в модуле Trigger Controller.

## 4. Буфер и до-триггерные кадры

| Параметр | Контракт |
|---|---|
| Предыстория | `0 ≤ n_prev_frames ≤ 64` и `n_prev_frames < n_frames` |
| Общее количество кадров фрагмента | `2 ≤ n_frames ≤ 131072` |
| Количество фрагментов за START | `n_fragments ≥ 1`, дополнительно ограничивается размером выделенной памяти |
| Логический объём FIFO | **100 кадров = 9600 слов = 76800 байт** |
| Хранение | **[CURRENT]** 65 бит на слово `{TLAST,TDATA}`, физическая XPM FIFO 16384 слов с логическим лимитом 9600 |

**[REQ]** До триггера сохраняются `n_prev_frames` последних полных кадров и текущий незавершённый кадр; более старые полные кадры удаляются. **[CURRENT]** Контроллер выталкивает из FIFO целые кадры (до `TLAST`), не обрывая кадр посередине. После триггера остаточное количество лишних PRE кадров удаляется перед передачей.

**[REQ]** Кадр, содержащий фронт принятого триггера, является **первым post-trigger кадром**, включая случай совпадения триггера с `TLAST`. Всего в успешном фрагменте записывается **ровно `n_frames` полных кадров**: `n_prev_frames` до него и `n_frames − n_prev_frames` после, считая кадр триггера.

**[REQ]** Переполнение FIFO — фатальная ошибка; новое содержимое не должно молча перезаписывать непрочитанные данные; ядро инициирует контролируемое завершение уже принятых AXI-транзакций и переходит в `ERROR`. **[CURRENT]** `fifo_overflow_count` считает отвергнутые записи (слова), а не обязательно единичные эпизоды переполнения; это отдельный предмет решения.

## 5. Формат фрагмента в DDR

**[REQ]** Формат: **128 байт преамбулы + `n_frames × 768` байт кадров**. Адрес начала фрагмента кратен 128. Все кадры передаются в исходной последовательности слов, без переупаковки. Строго little-endian для многобайтовых полей преамбулы.

| Смещение, байт | Размер | Поле |
|---|---:|---|
| `0x00` | 4 | `header_id`, программируемый идентификатор |
| `0x04` | 4 | `fragment_index`, начиная с 0 в каждом запуске |
| `0x08` | 8 | Защёлкнутый `timestamp` |
| `0x10` | 8 | Защёлкнутый `trigger_data` либо 0 |
| `0x18` | 32 | `aux_data` из 8 регистров AXI-Lite |
| `0x38` | 72 | Padding: повторяемые 32-битные слова `0x12345678` |
| `0x80` | 768 | Кадр №0; далее последовательно все кадры |

**[CURRENT]** В RTL преамбула выдаётся шестнадцатью 64-битными словами, первый — `{fragment_index, header_id}`, слова 7–15 — `0x1234567812345678`. Ровно 16 слов на burst и 6 bursts на кадр. **Количество burst-фрагмента:** `1 + 6×n_frames`.

### Объём памяти

```
fragment_bytes = 128 + 768 * n_frames
run_bytes      = n_fragments * fragment_bytes
fragment_addr(i) = mem_addr + i * fragment_bytes
```

**[REQ]** Перед разрешением START проверяются параметры, границы 32-битного адресного пространства и весь буфер: `run_bytes <= MEM_BUFFER_BYTES`; `mem_addr` кратен 128; `MEM_BUFFER_BYTES > 0`; исключается 32-битное переполнение адреса. Граница окончания интервала считается **исключительной**; ровно `2^32` допустимо как конец диапазона.

**[CURRENT]** Дополнительно writer проверяет **каждый burst** `addr .. addr+127` на принадлежность разрешённому диапазону. Отдельная проверка нужна для защиты от ошибки адресной логики после START.

## 6. Интерфейс памяти AXI3

**[REQ/CURRENT]** M_AXI basic write master, ширина WDATA 64, канал `AW/W/B`, `AWLEN=15`, `AWSIZE=3`, `AWBURST=INCR`, каждый burst 128 байт; частично заполненных burst нет. `WSTRB=0xFF`. Задержки `AWREADY`, `WREADY`, `BVALID` должны корректно обрабатываться с сохранением `VALID/DATA` до handshake. Максимум **4 незавершённых по BRESP AW** (`MAX_OUTSTANDING=4`).

**[CURRENT]** Одновременно активен один источник дескриптора burst, но ранее выданные AW могут ожидать B-ответа — это не четыре полностью параллельных канала подачи burst. Все IDs сейчас равны нулю; ответы сопоставляются по порядку выдачи AW. Успех фрагмента устанавливается **только после всех корректных BRESP**, а не после передачи последнего WDATA.

## 7. Управление и состояния

Состояния (значения в регистре STATUS, реализация):

`0 IDLE → 1 BUFFER_FILLING → 2 TRIG_WAIT → 3 DATA_TRANSFER → 4 AFTER_TRANSFER → (1 BUFFER_FILLING | 6 END_STATE | 0 IDLE)`.

При фатальной ошибке — `5 ERROR`, возврат по разрешённой команде очистки после безопасного завершения, сброса FIFO и освобождения пути записи.

- `START`: только из `IDLE` без неснятых ошибок; сначала многотактовая проверка SHADOW-параметров, затем атомарная фиксация ACTIVE и заполнение FIFO.
- `TRIG_WAIT`: хранение PRE окон, ожидание принятого триггера.
- `DATA_TRANSFER`: передача преамбулы и полных кадров, текущий кадр не обрезается.
- `AFTER_TRANSFER`: очистка FIFO, ожидание готовности, следующий фрагмент либо END.
- `STOP`: завершить текущий кадр камеры, не записывать неполные кадры; если триггера ещё не было — без DDR-записи; в передаче записать только доступное число **полных** кадров и дождаться BRESP; результат отметить как частичный/остановленный; затем `IDLE`.
- `ERROR`: новые burst не выдавать, уже принятые AW/W/B корректно завершить/дождаться; после восстановления — явное действие PS.
- `END_STATE`: конец заданного числа фрагментов; выход в IDLE по команде от PS.

**[REQ]** Приоритет при совпадениях: STOP выше триггера; fatal error выше обычного STOP. **[CURRENT]** На STOP выдаётся уточнённый `stop_target_frames` для `burst_packer`, а `halt_new` применяется только при фатальном прерывании.

## 8. Конфигурация, статус, диагностика

**[REQ]** Полноценный 32-битный AXI4-Lite slave, без IRQ; конфигурация `n_frames`, `n_prev_frames`, `n_fragments`, `MEM_ADDR`, `MEM_BUFFER_BYTES`, триггеры, header ID, AUX; команды START/STOP/CLEAR; статус FSM и ошибок; статистика DDR и триггеров.

**[CURRENT]** SHADOW можно обновлять во время активного захвата, но ACTIVE не меняется до следующего успешно проверенного START. Пока START проходит проверку — SHADOW-конфигурацию записывать запрещено во избежание TOCTOU. Регистрная карта: [register_map.md](register_map.md).

**[CURRENT после патча №4]** `triggers_accepted_total` и `triggers_missed_total` — **48-битные** счётчики modulo `2^48`, представленные 64-битными регистрами чтения с нулями в старших 16 битах. На внутренней реализации каждый счётчик разделён на три 16-битных сегмента. Этот выбор **не содержался в исходном ТЗ**; подлежит согласованию.

## 9. Тактирование, реализация, ограничения

- **[REQ]** Один `clk = 200 МГц`, без отдельного домена DDR-ввода в проекте IP.
- Внешний `ext_trig` асинхронен и проходит синхронизацию; временная привязка к камере имеет соответствующую неопределённость.
- **[CURRENT]** XPM BRAM FIFO и поведенческий FIFO для тестов; при штатной сборке `USE_XPM=1`.
- **[VERIFY]** Фактическое выполнение Timing после placement/routing в Block Design с PS, подключение clock/reset и реальная конфигурация HP-порта.
- **[VERIFY]** Длительность и распределение блокировок DDR/HP в реальной системе не известны; 100 кадров FIFO не гарантируют отсутствие переполнений при произвольно долгой остановке DDR.

## 10. Критерии приёмки

1. Сохранение точного содержимого и порядка 96 слов всех записанных кадров и 128-байтной преамбулы.
2. Корректная выборка PRE и первого POST при триггере в середине кадра и на TLAST.
3. START с некорректными параметрами отвергается **до** DDR; адрес и размер памяти проверяются без арифметического wrap.
4. `S_AXIS_TREADY` не опускается; потеря записи/повреждение кадра приводит к диагностируемой ошибке.
5. Никакого незаявленного AXI3 burst за пределами буфера; ошибки BRESP фиксируются; успешный фрагмент предполагает все `OKAY` BRESP.
6. STOP и ERROR не оставляют «висящих» принятых транзакций при отвечающем AXI slave.
7. Регрессионные тесты для XPM и поведенческого FIFO и долгого потока проходят.
8. **[VERIFY]** После Place & Route все Setup/Hold/и остальные релевантные Timing constraints выполнены при 200 МГц.

## 11. Что в ТЗ является реализационным решением

Фиксированные **100 кадров буфера**, **48-битная статистика**, **паддинг 0x12345678**, **две burst-банки**, **четыре outstanding BRESP**, отдельные счётчики некоторых стадий и двойная защита диапазона — разные по степени обязательности элементы. Матрица оценки: [architecture_review.md](architecture_review.md). Изменения интерфейсов и регистрационной карты требуют отдельного решения — не следует автоматически объявлять их «избыточными».
